# Validation

The sequential recordings and installation checks below are retained as historical
evidence. The README now links to the shorter [simultaneous three-object demo](parallel_validation.md).
Its wrench channels include fingertip-pad contacts only; the older sequential
reports used whole-finger contact aggregation.

All three complete 60 fps recordings passed the raw-data and video validators.
Each recording covers ten optical pads and 22 pressure regions across both hands
(five MCP regions, five PIP regions and one palm per hand).

| Object | Frames | Duration | Frame rate | Peak depth | Peak pressure response | Result |
|---|---:|---:|---:|---:|---:|---|
| Sphere | 2731 | 45.5167 s | 60 fps | 1.597 mm | 0.6484 | Pass |
| Cube | 2731 | 45.5167 s | 60 fps | 1.971 mm | 0.4585 | Pass |
| Irregular polyhedron | 2731 | 45.5167 s | 60 fps | 2.598 mm | 0.4365 | Pass |

The pressure values are dimensionless simulated responses, not calibrated physical
pressure. All recordings use 240 Hz physics and 60 Hz sensor sampling. Depth and
pressure return exactly to zero in each release check.

For each object, both cross-palm hops passed the free-flight and destination-contact
checks. Fitting the initial free-flight trajectory gives vertical acceleration
approximately -9.81 m/s², with negligible horizontal acceleration; both destination
palms record a nonzero pressure response. This checks actual ballistic flight rather
than only an animated target trajectory.

The 2560 × 1600 combined video contains 8193 frames and lasts 136.55 seconds. It was
concatenated without re-encoding and fully decoded successfully, with no duplicated
or dropped frames reported by the decoder.

## Environment and installation checks

Verified on gpu21, Ubuntu 24.04.3, RTX 5090, Python 3.11, Isaac Sim 5.1.0.0,
Isaac Lab v2.3.2 (source extension 0.54.2, commit
`37ddf626871758333d6ed89cf64ad702aef127d0`), torch 2.7.0+cu128.

- Seven unit tests passed: channel/layout contracts, surface registration,
  normal/friction wrench sums, cancelling forces with a nonzero moment, and empty
  contact buffers. Contracts also check marker masks/order and standalone imports.
- The wheel was installed into a separate directory and exercised from outside
  the repository. Every bundled asset passed its SHA-256 check.
- The final wheel's 166 source/resource files are byte-identical to the tested
  installation, excluding generated bytecode. Kit, calibration, USD, texture and
  license files are included.
- The actual Omni UI image provider displayed three rendered frames from the
  relocated wheel. The minimal `examples/read_sensors.py` example produced finite
  arrays and index-fingertip depth/contact-force responses.

The runtime uses the explicitly selected Isaac Lab source. The base environment
has distribution metadata for a different editable Isaac Lab checkout (0.54.3);
`tools/doctor.py` prints both installed metadata and the actual imported source.
No runtime RevoBench directory is required.

For the shared eight-GPU host, an isolated launch was also verified:

```bash
CUDA_VISIBLE_DEVICES=3 python examples/slide_demo.py --shape polyhedron --headless \
  --device cuda:0 --kit_args="--/renderer/activeGpu=3" --fps 60
```

Here CUDA sees physical GPU 3 as logical device 0, while the Kit renderer is
explicitly assigned physical GPU 3. The startup log confirmed the intended GPU.
This avoided creating CUDA contexts on unrelated, nearly full GPUs during
parallel validation. Ordinary single-GPU use needs only `--device cuda:0`.

## Finger-dance orbit showcase

The README orbit uses two upright hands with wrist centers 0.16 m apart. PhysX
records the joint-driven motion at 240 Hz, sampled at 60 Hz; the path tracer replays
the measured link transforms with unchanged source materials and textures. The
camera makes one complete periodic orbit around the hands' shared centerline.

The 15-second motor sequence is simulated directly; all 900 measured poses are
rendered at 60 fps and 1600 × 1000, without post-render retiming. The looping
640 × 400 GIF contains 450 frames at 30 fps over the same 15 seconds. Both media
files passed full decoding. Run `examples/finger_dance.py` to reproduce the dance.

The hands perform opposing finger waves, different sequences of pointing,
V-sign, three-finger and relaxed-fist gestures, opposing V-sign sway, and piano-like
individual and paired finger movements before returning to the initial pose.
Finger flexion targets are 1.05 / 1.12 / 0.82 rad for MCP / PIP / DIP; the thumb
stays outside the curled fingers. Quintic transitions keep target velocity and
acceleration continuous at each gesture boundary. The V-sign has a 12-degree
lateral sway target amplitude.

The maximum measured joint speed is 2.814 rad/s, below the configured 3 rad/s
limit. RMS tracking error is below 0.026 rad, maximum joint-limit violation is
below 0.000005 rad, and loop-seam joint error is below 0.000003 rad. Self-collision
remains disabled. Seven key poses and additional side/back views were inspected
for visible spacing, followed by 30 samples of the final video. These appearance
checks are not collision-free planning or physical contact validation.

Evidence: [simulation](evidence/orbit_simulation.json),
[render settings](evidence/orbit_render.json), and
[media validation and hashes](evidence/orbit_media.json).

## Scope

Signals are simulated and not calibrated against the physical hand. Collision and
compliant-contact parameters are demonstration approximations; visual skin is a
rigid mesh rather than a finite-element soft body. The UI provider was tested
headlessly; physical keyboard operation on a local display was not exercised.
The environment is a verified compatible existing installation, not a fresh OS
installation test. See the README for the pinned installation commands and model
assumptions.
